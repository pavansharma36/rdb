Why rdb

Stop juggling one tool per backend

rdb speaks SQL, documents, and queues from the same window — and stays small because the host ships no drivers.

🔌

Plugin architecture

Each backend is an out-of-process sidecar executable the host discovers at runtime. Connection forms and workspaces render generically from a plugin's declared config schema.

🗂️

Unified workspace

One window, a sidebar of saved connections, and a workspace per connection rendered according to its plugin kind — relational, document, or queue.

✏️

RDBMS editing

Browse schemas and tables, run SQL, and stage multi-cell edits — inserts, updates, deletes — that commit atomically in a single transaction.

📨

Documents & queues

Query MongoDB collections, and browse a RabbitMQ broker's overview, queues, exchanges, and connections — publish, get, and purge messages.

💾

Saved connections

Connection profiles persist across restarts as human-readable JSON in your OS app-data directory, organised per owning plugin.

🎨

10 built-in themes

Catppuccin Mocha & Latte, Dracula, Nord, Tokyo Night, Gruvbox, Monokai, Solarized, and GitHub Light — dark and light, your pick.

Under the hood

The host is a generic pipe

The Tauri host knows nothing about SQL, documents, or queues. It transports opaque JSON-RPC between the frontend and plugin sidecars over stdio.

  React + TypeScript frontend
            │  @tauri-apps/api invoke()
            ▼
  Tauri host (Rust, no DB drivers)
            │  line-delimited JSON-RPC over stdio
            ▼
  Plugin sidecars  ─  postgres · mongodb · rabbitmq
  (live PgPool / Client / HTTP handles stay inside the plugin)

Prefer the source

Build it yourself

Requires Rust (stable), Node.js 18+, and the Tauri 2 system dependencies.

git clone https://github.com/pavansharma36/rdb
cd rdb
npm install

# Build the bundled plugins, then point the host at them:
npm run plugins:dev
RDB_PLUGINS_DIR=$PWD/dev-plugins npm run tauri dev

# Or build a release bundle:
npm run tauri build
